一、实验目标

本实验不试图复现 SAT 的固定团队或 peer 协作收益。它只回答一个更窄、可归因的问题：在 Goal-Plus 的隔离候选拓扑中，“独立审计 + 有界诊断 + 候选修复”这条回路，能否在 VLIW 任务上提高答案质量，并且增量可以拆到生产、投递和闭环三个环节。

Goal 1 · Effect

效果目标

在 EdgeBench VLIW 官方 Judge 下，比较审计回路是否改善 official score、cycles 和 correctness，而不是只看“有没有发出 brief”。

Goal 2 · Attribution

归因目标

把“多一次 verifier 调用”“审计是否送达”“候选是否真的修复”拆开，分别估计生产、投递、闭环的增量。

Goal 3 · Boundary

边界目标

验证方案没有靠 peer 通道、没有让 verifier 改写 artifact、没有绕开 hard Evidence 或 Selection 来“制造提升”。

研究问题与主对照

研究问题主对照主要看什么不能回答什么
RQ1 审计生产N1 − N0vaudit precision、auditable rate、缺陷类型、briefs per record不能说明投递有效；N1 只生产不投递
RQ2 投递N2 − N1official score、delivery rate、uptake、repair lift不能说明闭环有效；N2 没有回执
RQ3 闭环N3 − N2verified rate、repair lift、harm、time-to-repair不能说明 SAT 团队协作整体有效
RQ4 成本与边界N0v − N0（可选）；N2/N3 成本tokens、cost、verifier calls、latency、隔离与 hard Evidence 约束不能把“多调用一次模型”的成本差当成审计效果

成功标准

  • 硬门槛：correctness 不出现系统性回退；official Judge 结果可复算；hidden case 只在最终判定使用。
  • 主效应：N2−N1 或 N3−N2 的 official score 按赛事方向改善，且配对 95% CI 支持；否则报告负结果，不更换主终点。
  • 机制证据：审计有产出、brief 可送达、候选有回执、artifact 有变化；任何一步缺失，都不能跳到“分数提升”。
  • 成本可接受：token、verifier 调用和延迟增量在预算内；否则即使分数提升，也要报告代价。
  • 可归因：每个对比只改变一个环节；Pi 与 Codex 分开汇总，不合并成一个大样本。
先机制，后分数：如果 delivery 或 uptake 没有发生，分数差异不能解释为“审计有效”。如果机制成立但分数无变化，结论是“审计没有转化为更好的答案”，而不是“实验失败”。

二、新方案架构与 SAT 对应关系

方案只保留 SAT 的“审计—修复”回路，不复制固定角色和 peer 通信。下图有四条所有权边界：Verifier 审计、Steering 投递、Candidate 修复、Hard verifier / Selection 裁判。理解这四条边界，就理解了整个迁移方案。

读法：从左到右是阶段推进，每列内部从上到下是阶段内步骤。Hard verifier 的 hard facts 同时供 LLM 审计和最终结算使用。

Audit ownerLLM Verifier独立证据与诊断
Delivery ownerSteering / pull只负责送达；旧 push 关闭
Repair ownerCandidate拥有 edit surface
JudgeHard verifier + Selection保持不可改写

为什么不让 verifier 直接修：verifier 没有候选的 edit surface；直接改 artifact 会把“审计”和“修复”混在一起，也会污染 hard Evidence 的评估边界。

为什么用 pull 而不是 push：verifier 是异步的，候选可能在审计产出前已经结束 turn。持久化 + 拉取把时间解耦，不需要新增 host wait loop。

为什么送达还不够：工具返回 brief 不等于候选读了，读了也不等于改了，改了也不等于分数更好。所以 N3 增加候选回执，并用后续 hard settlement 生成 credential。

SAT 机制到 Goal-Plus 的对应

迁移的是“结构”，不是“角色”。SAT 的 critic 被 verifier 替换，peer message 被单向 brief + pull 替换，integrator 被现有 Selection 替换；repair 仍由候选自己完成。

SAT 机制Goal-Plus 对应处理保留 / 替换的理由
explorer / candidate pool相互隔离的 parallel candidates替换保留“多候选探索”，但不打开 peer 通道，也不共享草稿。
critic / peer auditLLM Verifier 的 VerifierAudit + VLIW hard facts替换审计需要独立性；用 verifier 替代固定 critic，避免新增角色和对话拓扑。
repair actionAuditBrief.repair + 候选下一次尝试保留把“下一步查什么”变成有界动作，但执行者仍是拥有 edit surface 的候选。
peer discussion单向 brief + 按需 pull替换只传递审计结论，不允许候选互相对话；投递是 transport，不是协作本身。
integrator现有 Selection / Promotion保留但不改整合仍由现有 hard/quality 规则完成；审计不能改写选择。
strategy bank / reflection冻结的 task reference + defect taxonomy部分保留先把审计信号验证清楚；本轮不做跨 run 学习，也不在线更新 verifier 策略。
fixed team / team phases不迁移舍弃Goal-Plus 没有固定团队；强行加入角色和阶段会违反候选隔离。
coverage vs selection gapcoverage + selection loss + audit precision保留为观测SAT 的经验是“有更好的候选”不等于“最终选中”；本实验把这些拆开测量。
与 SAT 的边界：本实验不声称复现 SAT 的团队收益，也不使用固定角色或 peer 通信。它检验的是一个更窄的问题：在 Goal-Plus 的隔离候选拓扑中，审计—修复信号是否有增量价值。

五、测量指标

指标分四层：硬终点、审计机制、行为变化、成本。每类都必须能从持久化 artifact 复算，而不是从 transcript 猜测。主终点是 EdgeBench VLIW 官方分数；correctness gate 是硬门槛，cycles 作为 VLIW 关键指标同时报告。

硬终点cycles（max / best / slowest）越低越好VLIW evaluator；同时报最大、最好、最慢 caseVLIW 主指标

测量规则

  • VLIW 不能用平均 cycles 掩盖慢 case：必须同时报告 max、best 和 slowest case；cycles 是越低越好。
  • hidden Judge 只做最终判定：public feedback 不能替代 hidden 结论；调参不得使用 hidden case。
  • Audit precision 需要独立标签：未被标注的 brief 记为 unknown，不记为 correct；不能用候选是否采纳来反推精度。
  • Delivery 不等于 uptake：工具返回 brief 只证明送达；accepted 也只证明候选口头接受；artifact change 才证明行为变化。
  • Credential 是 hard-evidence 关闭：verified 只表示后续 hard score/artifact 改善，不证明具体 defect 的语义被完全修复。
  • 配对与不确定性：以 task × seed/campaign 为配对单位；报告 paired difference、bootstrap 95% CI 和 MDE；Pi/Codex 分开。
  • 缺失数据：失败或 incomplete 的 campaign 不进入均值，单独列出原因；不把缺失当 0。
解释顺序：先看 briefs/delivered/uptake，再看 artifact change/repair lift，最后看 official score。机制不成立时，不解释分数。
