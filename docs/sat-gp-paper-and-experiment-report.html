一、论文核心思想

SAT 讨论的不是“让更多模型同时回答”，而是“当没有任何一个成员拥有完整解法时，团队能否通过交换部分推理、挑战具体主张、修复错误并重新综合，构造出单个答案中不存在的正确解”。论文把这种能力称为 collaborative computation，并把它做成可搜索、可冻结、可迁移的策略资产。

Problem

问题：分工本身是未知的

固定投票、固定辩论、预先任务分解，都假设“怎么合作”已经知道。SAT 把这个假设反过来：先保留固定团队，让阶段、角色和信息流在问题相关的互动中出现；测试时只执行冻结的策略，不再学习。

关键判据：超过“最强成员”还不够，因为不同成员可能分别答对不同题。真正要超过的是独立答案的 routing oracle：如果只是从现有答案里挑，理想路由就是上限；超过它，才说明互动产生了新解。

Mechanism

三个可学习对象

  • S：阶段列表，例如独立解题 → 具体审计 → 修复 → 综合。
  • τ：团队共同遵守的协作规范。
  • α：成员的持久角色与能力边界。

策略库在评测前通过反思式搜索选出，测试时冻结。每个策略还要求最终产生一份短而自洽的 credential：答案加上可被审计的推理依据。

论文最重要的两个结论：

1. 在数学/物理任务上，SAT 的 66.7% 超过最强成员的 48.8%、同预算线性化的 58.7%，也超过独立答案理想路由的 59.0%；这支持“互动确实产生了新解”。

2. 在知识/逻辑任务上，候选池覆盖率达到 87.9%，但最终准确率只有 72.8%；问题从“生成不出正确候选”转向“审计器选不出正确候选”。

论文的边界

  • 数学/物理的强证据不能直接外推到所有任务、模型和成本条件。
  • 凭证审计不是形式化证明；它仍可能漏掉“看起来合理”的错误。
  • demonstrability 的相关性不能直接当作因果干预效果。
  • 问答基准的收益不能直接外推到长程软件工程。

二、论文方案图示

SAT 有两个回路：评测前的学习回路，以及评测时的执行回路。学习回路决定“怎么合作”，执行回路决定“这次怎么得出答案”；两者在测试时被冻结策略分开。

为什么固定团队、冻结策略

固定团队让不同策略可以在同一组角色上比较；冻结策略防止测试时“边答边学”造成泄漏与不可复现。SAT 把“组织能力”当作非参数化资产，而不是给模型改权重。

为什么需要凭证审计

最终候选往往都“看起来合理”。SAT 不先看答案频率，而是逐份凭证找具体局部缺陷：算术错误、缺失情况、无根据假设、推导跳步。若都没有缺陷，才用答案频率做强平票。

从论文到工程的关键转折：SAT 最值得迁移的不是“多放几个 Agent”，而是“把交流、挑战、修复、依据保留设计成可检查的过程”；但 Goal-Plus 没有 peer 通道，也没有固定团队，所以必须把这套过程改造成单向审计—候选修复。

三、Goal-Plus 适配方案

Goal-Plus 的约束与 SAT 不同：候选之间隔离、没有 peer message、verifier 异步、FrozenSpec / hard Evidence / Selection 不可被审计改写。因此不能复制 SAT 的固定团队和团队阶段，只能迁移“审计 → 修复 → 硬证据”的结构。

一句话架构：LLM Verifier 负责审计，Steering 只负责投递，Candidate 负责修复，Hard verifier 与 Selection 保持裁判权。

Why

为什么 verifier 不直接修

verifier 没有候选的 edit surface；直接改 artifact 会把审计和评估混在一起，也会污染 hard Evidence。

Why

为什么是 pull

verifier 是异步的，审计产出时候选可能已经结束 turn；持久化 + 拉取把时间解耦，不需要 host wait loop。

Why

为什么还要 credential

工具返回 brief 不等于候选读了，读了不等于改了，改了不等于分数更好；credential 用后续 hard settlement 关闭最后一公里。

Precision 仍不可计算：没有独立 defect 标签。N3 的 4 条 rebuttal 明确表示 frozen process verifier 只暴露 small_seed_0/1/2 和 main_public_seed_123，无法生成 brief 要求的 per-case evidence；这是 evidence surface / task reference 问题，不是候选无理由拒绝。

第一个真实 audit 修复：N3 c004 的 accepted brief 来自 1543 cycles；候选修复后 hard settlement 为 1379 cycles，credential 状态 verified。这是本次迁移第一次出现 accepted → artifact change → hard settlement → verified credential 的完整链路，−164 cycles。
但 N3 没有超过 N2：N2 c004 在没有 closure 的情况下走 147734 → 1817 → 1482 → 1351；N3 c004 走 147734 → 1543 → 1379（repair）→ 1379 retain。N3 的修复改善了自己的候选，但 N2 的搜索路径仍然得到更低 cycles（1351 vs 1379）。因此“闭环机制成立”不等于“闭环带来最终收益”。

5.5 结果解读规则

  • 先看 briefs / delivered / uptake，再看 artifact change / repair lift，最后看 Judge 与 cycles。
  • 机制不成立时，不解释分数；N1 没有 delivery、N2 没有 closure、N3 有 pending 时，分数差异不能归因于 audit。
  • VLIW 必须同时报告 max、best、slowest case；不能只报平均 cycles。
  • hidden Judge 只做最终判定；public feedback 不能替代 hidden 结论。
  • Pi 与 Codex 分开报告；缺失或 incomplete 的 campaign 不进入均值。

六、结论

论文侧结论和本实验结论分开写。最新 N3 已经证明“修复可以发生”，但还没有证明“审计提高最终答案”。

Paper conclusion

论文侧结论

  • SAT 在数学/物理任务上展示了“协作计算”：最终准确率超过最强成员和独立答案路由 oracle。
  • 在知识/逻辑任务上，候选覆盖率 87.9% 明显高于最终准确率 72.8%，主要瓶颈转向审计与选择。
  • 固定团队、冻结策略、反思式搜索和凭证审计可以组合成可迁移的非参数化组织能力。
  • 这些结论不能直接外推到软件工程、所有模型或所有成本条件。
Experiment conclusion

本实验结论

H1 生产：N3 10/10 audit、N2 3/6、N1 6/8；producer 已能产出 brief，但 N2 只有 50% 完成率，precision 仍不可计算。

H2 投递：N2 1351 vs N1 1354，几乎持平；N2 有 2 条 delivered，但没有 closure/response/credential，不能归因于 delivery。

H3 闭环：N3 1 accepted / 1 verified；c004 1543→1379，修复机制成立。但 N3 1379 比 N2 1351 多 28 cycles，最终收益未成立。

总体：可迁移的是“局部修复能力”；尚不能证明它能稳定改善最终选择。

结论边界：

当前可以说：Goal-Plus 已具备“verifier 审计 → brief → candidate 修复 → hard credential”的可执行结构，且 N3 首次出现 verified repair。

当前不能说：audit 提高了 VLIW Judge、降低了 cycles，或闭环改变了最终候选。N3−N2 = −1.37 Judge；R=1；N2/N3 仍不是同批 R=3 配对。

下一步

  1. 修 evidence surface：4/6 N3 delivered 被 rebutted，原因是 frozen verifier 只暴露固定 case；收窄 brief 或提供可调用的 per-case surface。
  2. 清 pending 并跑 R=3：同批 N2/N3，同一 harness commit、同一 T/K/C/R；N0v/N1 也同批重跑，才能算配对 CI/MDE。
  3. 再决定 audit 去留：如果 repair 比例/verified rate 稳定但 N3−N2 仍为负，说明闭环改善可观测性和局部修复，不是最终选择。
