一页结论

本实验不完整复现 SAT。它要回答一个更窄、更可执行的问题：Goal-Plus + Pi（deepseek-v4-flash）或 Goal-Plus + Codex（gpt-5.6-sol）已有的并发候选、LLM verifier、steering 和固定 SAT-GP 协议，能否在 VLIW 任务上产生可归因的硬收益。

Goal

验证有效性

固定结构化协作是否优于 K=4 并行搜索基线，并定位收益来自哪个机制。

Primary

硬分数 + 机制

主终点是 EdgeBench VLIW 官方 Judge 分数；机制指标解释收益从哪里来。

单任务、单变体

只跑 vliw_kernel_optimization，不跑 50 题；Pi 和 Codex 是两个独立变体，各自固定模型，不混合比较。

二、实验边界：做什么、不做什么

边界先写清楚，避免把“固定协议有效性”误读成“SAT 复现”或“通用软件工程结论”。

本轮要做

  • 验证 A5 固定 SAT-GP 协议 相对 A1 并行搜索的硬收益。
  • 验证 A2 共享 cache/evidence 是否减少重复探索。
  • 测量 A3 verifier 是否识别出真实缺陷；只看识别质量，不看分数。
  • 测量 A4 steering 是否把识别转成修复闭环。
  • 用 EdgeBench VLIW 官方 Judge 给最终结果打分。
  • 输出 coverage、selection loss、repair rate、token/cost 等机会点指标。

本轮不做

  • 不训练/演化 SAT 的 10 个策略库；A5 是固定人工协议。
  • 不做凭证审计选择；A5 的 certificate/phase ledger 放到 Phase 2。
  • 不做异构模型团队；本轮所有候选使用同一模型。
  • 不跑 EdgeBench 50 题；只跑 VLIW 单任务。
  • 不声称结果可外推到全部软件工程或全部模型。
  • 不用 R=1 的结果做正式因果结论。
结论口径：本实验的结论应写成“固定 SAT-GP 协议在 VLIW 单任务上的机制与硬收益”，而不是“SAT 论文结论被复现”。策略库学习和凭证审计是后续阶段，不是本轮成功条件。

A1 · parallel search

4 个独立 candidate，无 verifier/steering/cache；peer Evidence 不可见。作为所有增量的基线。

A2 · shared evidence

shared cache 打开，候选可显式读取 peer Evidence；verifier/steering 关闭。测“共享是否减少重复”。

A3 · adaptive control + verifier shadow

adaptive_search 且 allocation=None；LLM verifier 记录 claim 和 text scores，steering 只诊断不发送。主要终点是 verifier 精度/召回，不是分数。

A4 · GP async steering

在 A3 的 adaptive 控制基础上真正发送 steering，记录 attempt、delivery、observation，并测 repair lift。

A5 · SAT-GP v2

固定角色、阶段边界、SAT repair policy。Phase 1 只看硬分数和 steering/repair；certificate 指标 Phase 2。当前 A5 steering 执行链有阻塞，见“当前实验状态”，修复前不能把 1373 当作 A5 协议收益。

为什么没有 A0？

本轮先验证 K=4 条件下的机制增量；单 Agent 和同预算线性化基线在 Phase 2 扩展，避免第一轮成本过高。

控制器冻结：A1–A5 不是 prompt 文案。GOAL_PLUS_CONTROLLER_EXPERIMENT={"mode":"aN"} 在 SearchSpec freeze 时安装 verifier、steering、shared cache 和协议；prompt 只负责告诉 agent 不要覆盖。该 env 必须进入 Goal Plus MCP server 的 env 白名单，否则运行时收不到。

执行 setup/check/doctor；确认 VLIW work/judge 镜像、Docker、Judge 端口、SAT Goal Plus 源和 API/Codex 鉴权。

证据：3 组 cell manifest、score 分布、cache/verifier 记录

过 headroom gate

若 A1 分数接近 ceiling、候选无差异或方差远大于预期效应，停止正式矩阵，调整 T/任务/指标。

证据：A1 分布、coverage、MDE 估计

跑 Phase 1 正式矩阵

每个变体 A1–A5，T=7200s，K=4，C=1，R=3 个独立 campaign；EdgeBench VLIW 官方 Judge。Pi 和 Codex 各自 15 个 campaign，分开汇总。

证据：每个变体 15 个 run、Judge 结果、token/cost、机制计数

计算 coverage / selection loss

从 candidate 记录和 process verifier 计算候选池最优、选中、seed 的关系；给出 best-of-K oracle 对照。

证据：coverage 表、selection loss 表、oracle 对照

计算 repair / 破坏率

对每个 steering attempt，找下一次硬验证，判断是否改善、是否破坏之前正确候选；统计送达/过期/未闭环。

证据：attempt→iteration linkage、repair lift、correct-destroyed rate

生成报告与决策

按 arm 给出硬分数、机制指标、成本、CI；按 Gate 2 判断是否进入 Phase 2。负结果也要输出机会点图。

证据：report.md、xlsx、campaign-summary.json、决策记录

十三、附录：T/K/C/R 与版本差异

T / K / C / R

  • T：一次 task trajectory 或一次 Goal Plus search 的墙钟探索预算。
  • K：同一 task cell 内实际并行工作的内部 subagent 数；GP 用 budget.max_parallel 固定。
  • C：同时运行的不同 task cell 数；本实验固定 C=1。
  • R：独立重复次数或 seed 数；正式阶段 R=3，不使用 C 代替。

v1 → v2 的主要变化

  • 目标从“SAT 风格实验”收窄为“固定结构化协作有效性”。
  • A3 从“分数识别收益”改为“adaptive 控制 + verifier 识别质量”；分数阶梯改为 A2−A1、A4−A3、A5−A4、A5−A1。
  • 正式 benchmark 从 local-vliw 改为 EdgeBench VLIW 官方 Judge 单任务。
  • R 从 1 改为正式 3；增加 pilot 和 headroom gate。
  • 新增 coverage、selection loss、repair rate、correct-destroyed、token/cost。
  • 凭证审计、学习策略库明确放到 Phase 2/3。

v2 → v2.1 的主要变化

  • 新增 Codex + gpt-5.6-sol（medium）A1–A5 EdgeBench preset；Pi 和 Codex 作为两个独立变体，禁止混合比较。
  • 明确 A5 必须与 A1–A3 使用同一 T；当前 2h A5 / 30m pilot 不是 matched comparison。
  • 记录 A5 steering 执行链阻塞：history_limit 缺失导致 0 diagnostics；.bench-runtime 编辑面噪声导致 diff 被移除、A3 出现 private_evidence。
  • 记录本地 pilot 现状：A1 稳定约 1.48–1.54k；A5 1373 与 A3 r2 1374 基本持平；A5 的 1373 来自第二个 Search run，不能直接归因于协议。
  • 修正测量口径：verifier_completed 按 verifier/records/ 计；A5 selection loss 不跨 run 混算；partial cell 不进入均值。
  • 新增 Gate 2 前置条件：A5 必须先有 steering-diagnostics 和 attempt，才讨论分数收益。
为什么只跑 VLIW 单任务？

本轮目标是验证机制和机会点，不是刷 EdgeBench 全榜。单任务可以复用官方 hidden Judge，同时把 Docker/Judge 成本控制在可迭代范围内；多任务扩展应在 Phase 1 证明机制有效后进行。

为什么 A3 不进入分数阶梯？

A3 的 steering 是 shadow，不会向候选发送消息，也不影响 selection。因此 A3 的硬分数预期与 A2 接近；如果把它当“识别收益”的分数差，会得到接近零的误导性结果。A3 应看 verifier 的 precision/recall 和 claim coverage。

如果 A5 没有提高分数怎么办？

先看机制：coverage 是否提高、selection loss 是否下降、repair rate 是否提高。若机制发生但分数不涨，说明收益被成本/选择抵消；若机制没有发生，说明协议没有真正执行。两种情况都是有效的机会点结论，不是“实验失败”。

什么时候进入策略库学习？

只有在 Phase 1 证明固定协议有可复现收益后，才值得投入离线反思/变异/跨题验证/冻结策略库。否则先修协议和指标，避免把“策略库学习”当成万能补丁。
