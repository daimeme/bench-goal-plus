四、实验边界

v3.1 的结论只覆盖“新审计方案在 VLIW 单任务上的归因”，不外推到旧协议、共享、push steering 或多任务。

本轮要做

  • 验证新 audit brief 能否被生产、送达、采纳和闭环。
  • 用 N0v 做 compute-matched 控制，N1 做 shadow，N2 做 pull，N3 做 closure。
  • 用 EdgeBench VLIW 官方 hidden Judge 给最终结果打分。
  • 报告 audit precision、delivery rate、uptake、repair lift、harm、cost。
  • Pi/Codex 各自独立；所有 N 组使用同一 T/K/C/R。

本轮不做

  • 不跑旧 A1–A5 主矩阵；只在“历史对照”需要时补跑。
  • 不启用旧 SAT 角色、阶段、collaboration protocol 或 push steering。
  • 不做 shared cache / allocation 的因子实验。
  • 不训练策略库；不做异构模型团队。
  • 不把单任务结果写成 EdgeBench 全榜结论。
结论口径：写成“新审计方案在 VLIW 单任务上的生产/投递/闭环增量”，而不是“SAT 论文被复现”或“旧 SAT-GP 协议有效”。

五、为什么可以去掉旧 A1–A5

旧组回答的是上一版问题；把它们放进新矩阵只会混淆审计生产、投递和闭环。去掉它们不影响新方案的归因，因为每个旧组都能被新组覆盖或被判定为不同假设。

结果层只占一半。v3.1 要同时证明“审计发生”“审计送达”“修复发生”“修复影响硬结果”。

最小可判定集合：official score、coverage、selection loss、audit precision、delivery rate、uptake、repair lift、harm、token/cost。缺少 delivery rate，N2 无法解释为“投递有效”；缺少 audit precision，N1 无法解释为“审计有效”；缺少 harm，N3 无法解释为“闭环安全”。

VLIW 特有的补充指标

  • time-to-threshold：首次达到 <18532、<2164、<1790、<1363 的墙钟时间。
  • best-so-far AUC：按时间积分的 best cycles；比较“更早变好”。
  • low-mode saturation：N0v best-of-K 与全 arm 最优差距；小于 5% 时最终分数对比功效不足。
  • invalid rate：任一 case 错误即 invalid；单独报告。

审计精度的标注方式

  • semantics / resource / confounded / untested：用冻结 simulator 复算，自动打标。
  • shortcut：换 seed/shape 复跑；若结果不变，标 true。
  • scope_drift：补跑 claim 声称的全部 case；失败则 true。
  • 无法机检的语义缺陷：2 人独立标注 + 第三人仲裁；记录 Cohen's kappa。

VLIW 的优势是大部分缺陷可机检，不要退化成“凭 verifier 自述”。

十、分析计划与归因阶梯

按 task/campaign 配对；正式结论用 3 个 campaign 的配对差值和 bootstrap 置信区间，不用单次均值。

对比解释主指标注意
N1 − N0v审计生产audit precision、auditable rate、briefs/record模型算力相同；差异主要在 broker/brief
N2 − N1投递增量（主终点）official score、delivery rate、repair lift必须确认 N2 真的送达；N1 不进入响应
N3 − N2闭环增量repair lift、harm、time-to-repair、verified/rejectedrebuttal 和 credential 必须真的发生
N2 − N0v审计+投递总体official score、coverage、cost不能拆生产/投递；需要 N1 作中介
N0可选：LLM verifier 算力本身official score、cost不进入主归因

统计规则

  • 正式阶段 R=3；报告配对差值的 mean 和 bootstrap 95% CI。
  • 不把 R=1 的单次结果写成“显著”。
  • 若 pilot 估计的 MDE 大于可观测效应，先调整任务/预算，或改用 time-to-threshold / AUC。
  • Pi 与 Codex 分开算；不合并 arm 均值。

审计精度的统计

  • 按 defect kind 分别报 precision/recall；不要只报总体。
  • 可机检缺陷用冻结 simulator 复算，避免 LLM 自评。
  • 语义缺陷用 2 人标注 + 仲裁，报 Cohen's kappa。
  • 审计精度与 repair lift 分开：识别对不等于修复对。
low-mode saturation 的处理：如果 N0v 的 best-of-K 与全 arm 最优差距小于 5%，最终分数对比统计功效不足。此时主结论改为 time-to-threshold、best-so-far AUC 和方差；不要用“N2 比 N1 低 30 cycles”这种接近噪声的差值写结论。

T / K / C / R

为什么 N0v 是 compute-matched 控制？

N0v 与 N1/N2/N3 都调用相同次数的 LLM verifier；差别只在是否生成可投递 brief、是否送达、是否闭环。这样 N2−N0v 不会被“多一次模型调用”解释。

为什么 N1 是 shadow？

N1 生产完整 brief 但不进入候选响应。它测的是审计精度和覆盖率，不消费发送机会；N2−N1 才是投递的干净增量。

为什么主终点是 N2−N1，而不是 N3−N2？

新审计方案的核心假设是“审计能改变候选的下一步”。如果 brief 送不到或送达后不被采纳，闭环没有意义；所以先看投递，再看闭环。

如果 N2/N3 没有提高分数怎么办？

先看机制：delivery rate、uptake、repair lift、harm。若机制发生但分数不涨，说明收益被 low-mode/成本/选择抵消；若机制没有发生，说明投递或审计合同没有真正执行。两种情况都是有效结论。

什么时候进入 Phase 3 策略库学习？

只有在 Phase 1/2 证明固定审计有可复现收益，且已有随机化投递和可机检标注后，才值得投入离线反思/变异/跨题验证/冻结策略库。
